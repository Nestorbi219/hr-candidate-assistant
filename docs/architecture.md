# Архитектура и настройки

## Диалог и форма

`config.yml` определяет русскоязычный NLU-пайплайн: токенизация, словные и символьные признаки, DIETClassifier, нормализация синонимов и fallback. MemoizationPolicy, RulePolicy и TEDPolicy управляют диалогом.

`hr_form` собирает роль, опыт, навыки и зарплату. `validate_hr_form` проверяет значения **во время заполнения**; опыт и зарплата поступают как текст и затем превращаются в числа. Это позволяет обработать «150к» до проверки числового слота. При ошибке слот возвращается к `null`, и бот повторяет вопрос. Роль и навыки извлекаются из сущностей NLU.

После формы бот показывает анкету и вызывает `action_evaluate_candidate`. Условия сохранения: опыт не меньше минимального для роли, score навыков строго больше 0.5, зарплатные ожидания не больше 120% прогноза учебной модели.

## Сопоставление навыков

`actions/skill_matching.py` содержит нормализацию синонимов и два режима.

| Режим | Расчёт | Особенности |
| --- | --- | --- |
| `lexical` (по умолчанию) | Число совпавших уникальных навыков / число уникальных требований | Локальный, быстрый; дубли не повышают score. |
| `fasttext` | Косинусное сходство средних векторов навыков | Сохранён подход исходного проекта; требует Gensim и большой предобученной модели. |

Эти значения имеют разный смысл. В словарном режиме процент означает покрытие требований, в FastText — семантическое сходство. Одинаковый порог оставлен для демонстрации, он не калиброван на реальных анкетах. Синонимы — упрощение: например, PostgreSQL сопоставляется с SQL, TensorFlow — с deep learning.

Чтобы включить FastText:

```bash
python -m pip install -r requirements-semantic.txt
python -m gensim.downloader --download fasttext-wiki-news-subwords-300
export SKILL_MATCHER=fasttext
rasa run actions
```

Нужны свободное место, интернет для первого скачивания и память для загрузки модели. Модель англоязычная; русские названия покрываются лишь явными синонимами. Веса не входят в репозиторий; условия источника доступны в [каталоге Gensim](https://github.com/piskvorky/gensim-data). Настройка `FASTTEXT_MODEL` позволяет выбрать совместимую модель Gensim с известным `vector_size`.

## Учебная модель зарплаты

`data/salary_demo.json` содержит 20 примеров из первоначального скрипта. Признаки: опыт и TF-IDF навыков. Pipeline: StandardScaler → RandomForestRegressor с `random_state=42`. Модель строится при первом вызове и хранится в памяти; импорт не создаёт pickle-файлы.

Роль из примеров в признаки не включается — это ограничение исходного подхода. Нет независимой тестовой выборки, рыночных данных и оценки качества. Модель демонстрирует интеграцию ML с ботом.

## Хранение и переменные

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `CANDIDATE_DATA_DIR` | `runtime` | Папка для локальных заявок. |
| `EXPORT_EXCEL` | `false` | При `true` дополнительно создаётся `candidates.xlsx`. |
| `SKILL_MATCHER` | `lexical` | `lexical` или `fasttext`. |
| `FASTTEXT_MODEL` | `fasttext-wiki-news-subwords-300` | Имя модели в каталоге Gensim. |

Подходящие анкеты содержат sender_id, роль, опыт, навыки и зарплату. JSONL — основное хранилище; Excel пересобирается из него. Синхронизация записи защищает один процесс, но не несколько серверов. При нестандартной папке убедитесь, что данные не попадут в Git.

Токены задаются только в игнорируемом `credentials.local.yml`. `.env` не загружается автоматически. Duckling не нужен: опыт и зарплата разбираются локально.
